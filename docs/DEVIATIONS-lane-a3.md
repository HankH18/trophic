# DEVIATIONS — Lane A3 (core/battle.ts — the battle reducer)

Staged separately because Lanes A1/A2/A4 hold `docs/DEVIATIONS.md` concurrently, which is the same
convention `docs/DEVIATIONS-lane-a2.md` and `docs/DEVIATIONS-lane-b.md` already follow.
**Merge into `DEVIATIONS.md` at integration.**

Rows `D-A3-1…` are deviations of the reducer as built. Rows `D-A3-R1…` were introduced by the
repair pass that followed the adversarial audit; each names the defect it fixed, because the fix is
itself a departure from the letter of the build doc in several places.

## Built

| # | Spec ref | Deviation / finding | Rationale & action |
|---|---|---|---|
| D-A3-1 | build-doc §7.4 | **`step()` takes a fourth parameter.** The doc's signature is `(BattleState, Action, rng) => {state, events[]}`; the shipped one is `step(state, action, rng, ctx)`. | The reducer must read `data/*.json` (species, moves, type chart, balance) and the derived food web, and L11 forbids it from importing anything engine-shaped to get them. `createBattleEngine(ctx)` returns the doc's exact three-argument shape closed over the content, so the documented signature is what callers hold; the four-argument form is the underlying pure function that the tests and the harness drive directly. |
| D-A3-2 | build-doc §7.4 damage chain | **A crit multiplier is appended to the §7.4 formula.** The doc states `damage = (atk × movePower / def) × typeMult × predation × roll(0.9,1.1)`; the shipped chain multiplies by `critMultiplier` (and, for a defender that is mid-Burrow, by the evade reduction). | bible §2 makes Instinct "crit chance" and the §7.4 `damage` event carries a `crit` flag, so a crit factor is required by the same documents; §7.4's line simply does not restate it. Both extra factors are `balance.json` values and both are the multiplicative identity when absent, so the doc's formula is recovered exactly with no crit and no evade. |
| D-A3-3 | bible §3 Burrow/Roost | **"+evasion" is implemented as a reduction of incoming damage** (`×(1 − moveEffects.magnitude.evasionBonus)`), not as a miss chance. | A miss chance needs a to-hit roll, and TROPHIC has no accuracy stat anywhere in bible §2's five. Damage reduction spends no extra RNG draw, keeps the documented draw order hand-checkable, and cannot produce the "your attack missed" beat the bible never describes. See D-A3-R6 for the turn-order half of this move. |
| D-A3-4 | build-doc §7.4 catch | **The snare's three shakes are `p^(1/shakes)` each.** The doc gives one probability `p`; the bible gives snares dramatic shakes without numbering them. | All three shakes passing has probability exactly `p`, so the §7.4 formula is untouched while the shake count the UI animates is real rather than decorative. `balance.catch.shakes` is the tunable. |
| D-A3-5 | build-doc §7.4 `Battler` | **`BattleBattler extends Battler` with `xp`, `boons` and (since D-A3-R2) `metamorphosed`.** | `Battler` (core/types.ts, lane A1's file) carries no XP, and the reducer must bank XP across a multi-enemy fight and rebuild stats on level-up without losing a retirement boon or the metamorphic latch. The extension is additive — a `BattleBattler` IS a `Battler`, so `BattleState` is still exactly the §7.4 shape — and `xpOf()`/`boonsOf()`/`metamorphosedOf()` read it back off a plain `Battler`. |
| D-A3-6 | bible §11 / build-doc §7.8 | **Bag keys are the ids the actions already carry**: snare tier names (`base`/`weighted`/`master`), bait tags (a role name or a species line id), and `balance.medicine.salveItemId`/`tonicItemId`. A key absent from `bag` is treated as untracked rather than empty. | Nothing in the doc names the bag's key space, and inventing a second id vocabulary would mean a lookup table mapping actions to bag keys — a shadow table in the §8.3 sense. "Absent = untracked" is what lets the balance harness run battles with no inventory at all. |
| D-A3-7 | build-doc §7.2 "Derivations (never stored)" | **Each `fixtures/battle-scripts/*.json` stores the derived `FoodWeb` it was recorded against.** | A fixture is a RECORDING, not game state: it must replay byte-identically years from now, which it cannot do if the web underneath it silently changes. The stored copy is not a second source of truth — `tests/unit/battle.test.ts` re-derives the web from `data/nodes/*.json` through core/foodweb.ts and fails if the two ever differ (and, since D-A3-R10, does the same for the gym fixture's roster against `data/gyms.json`). |
| D-A3-8 | build-doc §7.4 turn order | **An exact Speed tie resolves in the player's favour, and the enemy policy is a deterministic argmax** on expected damage (mid-roll, no crit) rather than a randomised AI. | Both spend zero RNG draws, so the documented draw order stays hand-checkable and a scripted stream is readable; and the §10.5 harness win rates become a property of the numbers rather than of a dice-rolling AI. |
| D-A3-9 | build-doc §6 INV-4 / G11 | **Two gameplay tunables live in `data/balance.additions.A3.json`**, not `balance.json`: `battle.evadeTurns` (bible §3 names Burrow/Roost's evasion without a duration) and `battle.statusWearOffTurns` (see D-A3-R7). | `data/balance.json` is lane A1's file and the orchestrator merges the additions at integration; the alternative was a literal in code, which G11 forbids outright. core/battle.ts prefers a merged `balance.battle` group when it is present. **Merge order matters:** core/ imports the additions file, so it may only be deleted in the same change that removes the import. |

## Repaired (post-audit)

| # | Spec ref | Deviation / finding | Rationale & action |
|---|---|---|---|
| D-A3-R1 | build-doc §7.4 / bible §11 | **A medicine may no longer be used on a fainted battler, nor spent for no effect.** `isActionLegal` previously checked only the item id, the side and bag stock. | A salve on a fainted teammate healed it above 0 HP without clearing `fainted`, producing a battler that broke the reducer's own `fainted === (curHp === 0)` invariant, could never be switched in, and was still counted as down by the loss check — a consumed item for a permanently incoherent creature. KO is a faint and there is no revive anywhere in bible §11's medicines, so the action is refused. A salve at full HP and a tonic with no status are refused for the same reason (the item is not spent). The property suite's action generator now aims medicines at benched and fainted teammates; it previously only ever emitted an untargeted salve, which is why the defect was unreachable from it. |
| D-A3-R2 | build-doc §7.4 metamorphic jump | **The metamorphic latch is resolved once at `makeBattler` and CARRIED** on `BattleBattler`, and `CaughtIndividual` now reports it. | `levelUps()` re-derived the latch from the age class, so a battler specced `metamorphosed:false` gained a phantom ×1.15 on every stat the moment it levelled mid-battle (and an explicit `true` on a Juvenile lost 13%). Separately, `caughtIndividual()` did not report the latch at all, so the catch hand-off could not set `OwnedCreature.metamorphosed` and core/lifecycle.ts had to guess — the two modules' defaults disagreed by 15% on the same wild-caught adult. bible §4 ("Wild adults of a line only appear in evolved form") makes the age the right default, and `hasMetamorphosed` in this file remains its single implementation, which core/lifecycle.ts imports. |
| D-A3-R3 | bible §3 durations | **Stat-mod durations tick for EVERY battler, not only the two on the field**, and their expiry is announced in `events[]`. | Durations are stated in turns ("Terrify: enemy −Attack 2 turns"), so a buff parked on the bench used to freeze at full strength and come back intact any number of turns later — free for the player and a distortion the §10.5 harness would have measured as a real win rate. The **status chip** deliberately still ticks only for the active pair: a status is a condition of the creature that is fighting, `persistUntilCured` keeps it on the bench without chipping, and chipping the whole party every turn would make switching lethal in a game where KO is a faint. |
| D-A3-R4 | build-doc §15 C3 / core/types.ts `BattleEvent` | **A stat modifier's expiry is emitted as `statChanged` with `turns: 0`.** | The union in core/types.ts (lane A1's file, read-only here) has no expiry member, and the renderer's only narration channel is the log: a buff icon could go up on `statChanged` and never come down at the right moment. `turns: 0` reads as "this modifier ended" and needs no schema change. See the BLOCKER below for the three events that could not be expressed this way. |
| D-A3-R5 | bible §1 / build-doc §6 INV-3 | **`balance.types.neutral` is no longer used as the multiplicative identity** for the absent predation, crit and lure factors; those use the literal `1` (`ABSENT`). | bible §1 says the type multipliers are "tunable via the balance harness", and §10.5 has that harness rewrite `balance.json` overnight. With `neutral` standing in as "×nothing", doubling it multiplied typeless damage by 8 and doubled catch odds — a tunable with a second, undocumented job, which is exactly what INV-3 promises cannot happen. `1` is arithmetic, not a gameplay constant, and the file header already sanctions structural identities (the `1 +` of `1 + 0.02×level`). |
| D-A3-R6 | bible §3 Burrow/Roost | **An `evade` move resolves before the opponent's action** (priority 1, the same rank Ambush uses on its entry turn). | The evade lasts `battle.evadeTurns` (1) and covered only the remainder of the turn, so a user slower than its opponent had already been hit when it applied: the move did *nothing at all* for roughly half the roster, while being a full turn's cost. A duck that lands after the blow is not a duck. The duration is unchanged, so nothing gets stronger — the faster case behaves exactly as before. This is a rule in code, not a constant (the duration and the magnitude are both data). |
| D-A3-R7 | build-doc §7.4 statuses | **`balance.status.persistUntilCured` is now read**, with a companion `battle.statusWearOffTurns` that is consulted only when the flag is `false`. | The flag was declared in `Balance`, validated by the zod schema and read by nothing: retuning it was a silent no-op, the failure mode `docs/DEVIATIONS.md` D19 deleted two other constants to avoid. `balance.json` is another lane's file, so removing the knob was not available; wiring it was. With the shipped `true` the behaviour is bit-identical to before (build-doc §7.4 names no expiry), so this adds no mechanic to the shipped game — it makes an advertised knob mean something when the harness turns it. |
| D-A3-R8 | bible §1 / build-doc §15 C3 | **The `effectiveness` band a `damage` event reports is COUNTED, not measured off the product.** One super-effective half and one resisted half now report `neutral`. | `1.5 × 0.67 = 1.005`, so a Fire move into Plant/Earth (Barkhide) or Water/Poison (Mirefin) announced "super-effective" for a hit worth +0.5%. The multiplier is unchanged — only what the renderer is told. Counting also makes the band immune to a type-chart retune, so the announcement cannot drift away from the arithmetic in either direction. `tests/unit/battle.test.ts` previously pinned the old reading; that expectation was corrected, with the reason recorded in the test. |
| D-A3-R9 | build-doc §7.3 / §7.4 predation | **`PredationOracle` is node-aware**: `eats(predator, prey, nodeId?)`, and the reducer passes `BattleState.nodeId` down. | §7.3 derives edges per node and §7.4 defines predation as "the attacker's derived diet includes the defender's line". An oracle built from several webs (a gym fight handed the region) unioned them, applying the ×1.25 to pairs no single node's derivation contains. A battle that names a node the oracle holds now reads that node's web; anything else falls back to the union, which is documented on the interface. |
| D-A3-R10 | build-doc §8.3 `no_shadow_tables` | **`baitMatchOf` no longer restates the §7.2 bait rule** — it hands core/foodweb.ts's `baitMatchFor` the edges the oracle already derived and reads the answer. | The species/role/flora-Producer logic was duplicated in battle.ts and, because the sanctioned oracle constructor never set the optional `baitMatch` hook, the duplicate was the live path for every caller in the repo. An agreement test is not structural incapability; delegation is. The equivalence test over all 12 nodes stays, now as a guard on the delegation rather than on two implementations. Also in this row: the gym fixture's roster is now gated against `data/gyms.json` (its embedded food web already was), so a bible §7 retune cannot leave the fixture silently stale. |
| D-A3-R11 | build-doc §7.4 | **`startBattle` refuses a side with no standing battler, and fields the first STANDING one.** | An all-fainted party made every action a legal no-op with no outcome — the battle could never end — and `playerOrder[0]` could field a fainted battler while a healthy teammate stood behind it. A party may still CARRY fainted members; it may not consist only of them. This is the same class of caller error as the empty party the function already rejected. A snare aimed at a fainted wild target is refused for the matching reason (its 0-HP catch odds were the best in the game, and `caughtIndividual` would have handed the caller a corpse to decrement out of the node population). |
| D-A3-R12 | bible §3 Lure | **Lure only takes effect when the PLAYER's side uses it.** | `state.lureActive` was side-agnostic, so an enemy that used Lure raised the player's catch odds ×1.5 on its own head. Only the player throws snares. |
| D-A3-R13 | build-doc §7.4 flee | **`fleeChance` no longer substitutes `flee.clampMax` for the speed RATIO** when the opponent's Speed is 0. | A probability where a ratio belongs: it produced `0.4 + 0.4 × 0.95 = 0.78` where the formula's own limit is the 0.95 cap. `mySpd / 0` is `+Infinity` and the existing clamp answers correctly; `0/0` is taken as `+Infinity` too rather than `NaN`. Unreachable with shipped data, so this was a latent trap rather than a live bug. |
| D-A3-R14 | build-doc §6 INV-3 | **`illegalActionReason(state, action, ctx)` is exported**, and `isActionLegal` is now public. | A rejected action returns the same state object and an empty event array, which a UI cannot tell apart from "nothing happened" and a harness can spin on forever; the `BattleEvent` union has no rejection member and is not this lane's file. A caller asks for the reason BEFORE stepping — that is the signal, and it is a string a UI can show. |
| D-A3-R15 | build-doc §6 INV-3 | **The merged-`balance.battle` read is checked, and a bad merge throws.** | The old lookup was `(content.balance as unknown as {battle?: {evadeTurns?: number}}).battle` with a silent `??` fallback to the additions file: after the merge, a renamed, mistyped or half-merged group would have lost quietly to the fallback and every retune of `balance.json` would have been a no-op that looked applied. A `battle` group that exists must now carry every key, as a finite number, or the context refuses to build. |

## BLOCKER for the integrator — `core/types.ts` (outside lane A3's file scope)

Three things the reducer does are invisible to a renderer that reads only `events[]`, and all three
need a new member on the `BattleEvent` union in `core/types.ts`, which this lane may not edit:

```ts
| { t: "evaded"; uid: string; moveId: string; turns: number }        // Burrow/Roost went up
| { t: "lureChanged"; uid: string; active: boolean }                 // catch odds ×1.5 on/off
| { t: "actionRejected"; reason: string }                            // what illegalActionReason says
```

Until they exist the information is still reachable — `BattleState` carries `statModTurns`
(the evade's marker) and `lureActive`, and `illegalActionReason()` answers the third *before* the
step — so nothing is lost, only the narration. `statChanged { turns: 0 }` (D-A3-R4) covers stat-mod
expiry without a schema change; the evade and the lure have no truthful existing member to ride on,
and inventing one (a fake `statChanged` on a stat that did not change) would be worse than the gap.

A second, smaller one: `Balance` in `core/types.ts` has no `battle` group, so the merged-value read
in `makeBattleContext` needs one cast (D-A3-R15). Adding `battle: { evadeTurns: number;
statusWearOffTurns: number }` to `Balance` **and** to `zBalance` in `core/schemas.ts` — a plain zod
object strips unknown keys — removes it. See `data/balance.additions.A3.json`'s `_merge` note.
