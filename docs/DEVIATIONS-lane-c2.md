# DEVIATIONS — Lane C2 (overworld: painted map + mask movement + encounters off node JSON)

Every departure this lane makes from `build-doc.md` or `content-bible.md`, and every project rule it
bends, with the reason. Indexed from `docs/DEVIATIONS.md`. Never a silent change.

Rows C2-D1 … C2-D4 date from the original C2 build and existed only as comments in the source — a
departure that lives in a comment is a departure the next agent will not find, which is what
`.claude/CLAUDE.md`'s "never a silent change" rule is about. C2-D5 onward come from the repair pass
that followed the C2 audit.

Files this lane owns: `game/collision.ts`, `game/movement.ts`, `game/encounters.ts`,
`game/mapview.ts`, `game/wild-battle.ts`, `game/scenes/OverworldScene.ts`, `tools/collision-editor/`,
plus the routing half of `game/boot.ts`.

| C2-D1 | build-doc §7.7 (`NodeFile.adjacency`), §7.1 `PROP_KINDS` | **Travel between nodes is a KEYED action (`1`–`6` for the node's adjacency list), not a walk off the edge of the map.** | Nothing in the data says where an edge of a painted map leads. `NodeFile` carries `adjacency: string[]` and no exit positions; `core/types.ts` `PROP_KINDS` is `antler-stone`, `shell-kiln-shrine`, `sunken-idol`, `sign-card` — there is no door or portal kind to key a transition off, and inventing one would be inventing content (G2). A `door` prop kind with a position and a target would change this, and that is a content decision for the bible, not one to take here. |
| C2-D2 | build-doc §7.6 "Player logical sprite 32×48, tile step 32px" | **The player's collision footprint is ONE tile (32×32 world px) at the feet, not 32×48.** | The sprite is 48 tall because the art overhangs upward — head and cap — not because the creature occupies a tile and a half; a 32×48 footprint would make the player unable to stand with their head under an overhang they are drawn as passing under, and would put the movement grid and the collision grid permanently out of phase (32px step vs a 48px probe). `tileWalkable` tests exactly one tile step square at the feet; `spriteWorldPosition` puts the extra 16px of art above it. |
| C2-D3 | build-doc §16 G11 ("no gameplay constant as a literal") | **Walk pace (`DEFAULT_MS_PER_TILE = 160`) is a presentation default in `game/movement.ts`, not a key in `data/balance.json`.** Every call site can override it. | G11 governs numbers that change what the SIMULATION does. A foray is counted in STEPS (`balance.encounter.stepsPerForay`), so a faster or slower walk costs exactly the same ticks, meets the same number of creatures per foray, and moves no population differently — the balance harness would be measuring a feel value if it read this. It is the same class as C1-D1's text speed. **If a later lane wants it tunable it belongs in `balance.map`**, and `data/` was read-only to this lane. |
| C2-D4 | build-doc §7.6 (the mask), §8.2 (overlay-diff) | **The mask contract is declared in `game/collision.ts` `MaskPolarity` and enforced there: dark blocks, and a conforming mask is FULLY OPAQUE.** `majority` is the default cell policy; `any` exists for the editor. | §7.6 says "1-bit PNG at map native res, sampled on a 16px grid" and stops — it fixes neither the polarity nor what an alpha channel means, and two modules had each filled the gap differently (see C2-D7). | C2-D7 | build-doc §8.2 / Hard Req 5 / G4 | **A collision mask with ANY transparent pixel is REFUSED at load** (`collisionFromMask` → the synthesised placeholder, with the verdict printed), rather than being read one way or the other. | Two modules had each declared themselves the mask encoding and they contradicted each other: `game/collision.ts` read a transparent pixel as unpainted-therefore-walkable, `tools/overlay-diff/mask.ts` counted it toward a cell's total and never toward its walkable half — i.e. blocked. ## Known gaps this lane is NOT closing

- **`core/` has no wild-creature trait roller.** See C2-D5. Until it does, two implementations of one
  bible rule exist (`game/wild-battle.ts` and `tools/harness/player.ts`), both outside `core/`.
- **`core/foodweb.ts` cannot say a line is sign-chain GATED.** `EncounterWeight` has `active` and an
  optional `dormantReason`, and a gated line comes back as `{weight: 0, active: false}` with no
  reason — indistinguishable in TYPE from a line at count 0. `game/encounters.ts` `absenceCauseOf`
  separates them by the live count, which is inference from the shape of what core returned rather
  than a restatement of core's gate rule (G3/G6), and `tests/unit/encounters.test.ts` proves the
  classification against core over every shipped node in every season. A `gated?: true` field on
  `EncounterWeight` would make the inference unnecessary; `core/` is read-only to this lane.
- **`balance.rng.subsystemTags` declares three streams (battle, sim, encounter) and no `lifecycle`
  one.** The overworld derives the heir stream as a child of `sim` through `core/rng.ts`
  `deriveStream`. Inherited from the original C2 build; still true.
- **The overworld HUD's panel is nearly screen-wide.** It now WRAPS at the virtual width, so no line
  runs off the right edge (it used to be 1044px on a 480px screen and cut the provenance line off at
  "…SYNTHESISED co"), but the panel is still as wide as its widest wrapped line and tall enough to
  overlap the centred player. It is a debug readout the vertical slice needs while the art is
  unbuilt; a designed overworld HUD is a later pass, not a C2 repair.
- **`game/main.ts`'s scene-list comment still says "`Battle`, `YearTurn` and `Retirement` are
  registered and IDLE".** `Battle` is now driven by the overworld. `game/main.ts` is lane C1's file
  and was being edited concurrently; corrected in the report rather than in the file.
