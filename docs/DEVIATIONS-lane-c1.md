# DEVIATIONS — Lane C1 (game shell: boot, storage, registry, placeholders, title/menus)

Every departure this lane makes from `build-doc.md` or `content-bible.md`, and every project rule it
bends, with the reason. Indexed from `docs/DEVIATIONS.md`. Never a silent change.

Rows C1-D1 and C1-D2 date from the original C1 build and existed only in its hand-off message; they
are written down here because a departure that lives in a message is a departure the next agent will
not find. C1-D3 onward come from the repair pass that followed the C1 audit.

| # | Spec / rule ref | Deviation | Rationale |
|---|---|---|---|
| C1-D1 | build-doc §16 G11; bible §12 "settings, text-speed" | **`TEXT_SPEED_CPS = {slow:15, normal:30, fast:60, instant:0}` lives in `game/registry.ts`, not in `data/balance.json`.** | G11 governs constants that change how the GAME behaves — damage, breed rates, catch odds — and its purpose is that a retune is a data edit with one home. Text crawl speed is a per-device display preference: a retune of balance must not be able to change how fast a message box draws, nor the reverse, and nothing in `core/` reads these numbers (the balance harness would be measuring a UI preference if it did). They are not in balance.json for the same reason the UI hex colours are not. If a later lane wants them player-editable as numbers, they belong in a settings file of their own. |
| C1-D2 | build-doc §7.8 (the save shape) | **Settings are stored under their own key, `trophic.settings`, outside the save file.** The key is derived from `core/save.ts`'s `SAVE_KEY_PREFIX` namespace, never spelled out twice. | §7.8 fixes the save's fields; adding a settings object to it would be a schema change to a shape `core/save.ts` owns and validates. Settings are also per-device rather than per-run — three slots share one text speed — and a corrupt settings blob must not be able to make a save slot unreadable. `loadSettings` falls back to the default on anything it does not recognise, and `tests/unit/game-storage.test.ts` asserts neither key can corrupt the other. |
| C1-D3 | locked decision L11 (by analogy) | **`game/boot.ts` takes the Phaser namespace as an argument (`createGameConfig(P, scenes)`) instead of importing it.** `game/main.ts` supplies it. | `import "phaser"` throws `ReferenceError: window is not defined` under vitest's node environment (measured, in `phaser/src/device/OS.js`), so a value import put every function in the file out of reach of every test in the repo — which is how `startNodeId`, `requestedSeed`, `integerZoom` and `contentIssues` came to ship with no assertion on them at all (G14). Only three engine VALUES were ever needed (`AUTO`, `Scale.NONE`, `Scale.NO_CENTER`). This is the same discipline L11 imposes on `core/`, one level up, and the same pattern the year-turn and retirement scenes already use (`createYearTurnScene(Phaser)`). `tests/unit/game-boot.test.ts` exists because of it. |
| C1-D4 | — (project rule: G14) | **`game/menu-model.ts` is new**: the title/menu screens' arithmetic — bottom-up layout, the warning-note composition, slot-row enablement, the scene-data guard — lives there, engine-free, and the scenes only draw and route. | Same root cause as C1-D3: a scene file cannot be imported by a test, so logic inside one is logic no assertion can reach. Three of the C1 audit's findings (a warning note overprinting the byline, slot messages naming no slot, an unreachable delete branch) were geometry and string composition sitting in a scene. The rule this establishes for the lane: **a scene may draw, route and listen; anything it decides lives in a module.** |
| C1-D5 | build-doc §16 G11 | **`game/placeholder.ts` imports `data/balance.json` directly**, as `game/boot.ts` already does, to read `map.virtualWidth`, `map.virtualHeight` and `map.mapRenderScale`. | A stand-in has to be drawable before `validateContent()` has run and before the registry holds content (the content-failure screen itself draws one), so it cannot read the balance through the registry. The numbers still come from `data/balance.json` — G11's actual requirement — rather than being restated as literals. They decide how often the placeholder's label repeats: one screenful of a texture is `virtual ÷ mapRenderScale` texture pixels, and a label further apart than that is a label the camera can miss. |
| C1-D6 | build-doc §15 (lane order) | **Every scene on disk is registered in `game/main.ts`, including three that nothing yet routes to** (`Battle`, `YearTurn`, `Retirement`). `game/scene-keys.ts` gains `dex` and `summary`. | Phaser answers `scene.start` on an unregistered key with a `console.warn` and a silent no-op, so an unregistered scene is unreachable however finished it is — the C1 audit found seven of ten in that state and the app dead-ended at the in-run menu. Registering them costs one line each and makes the lane that owns the driver a one-line change. Their drivers are NOT invented here: a battle needs a party (§15 C7 hands the starter over) and the year turn needs the clock's `yearEnd` (C6). A router that fabricated a creature to have something to fight would break G2; one that faked a year turn would break G6. `main.ts` says which scenes are routed and which are idle. |
| C1-D7 | build-doc §15 C2 (file ownership) | **ESC in the overworld is bound by C1's router (`game/boot.ts`), not by `game/scenes/OverworldScene.ts`.** | Without it the app is a one-way street: the player reaches the region and can never save, read the ledger, or leave. The binding belongs in the overworld scene, which is C2's file and outside this lane's scope, so it is installed from the router on the scene's own `create` event and guarded against double-binding. `OverworldScene` binds W/A/S/D, the arrows, C and 1–6, so ESC was free. **For lane C2:** move this into the scene when convenient — `bindSessionMenuKey` in `game/boot.ts` is the whole of it. |
| C1-D8 | — (cross-lane contract) | **The in-run menu calls `scene.stop(key)` on the ledger / dex / summary before reopening itself**, rather than relying on their `onClose` callbacks to close them. | Their `onClose` contract says "the caller decides what happens next", and `ScenePlugin.start` shuts down the scene it BELONGS to — the menu — not the one that called back. Measured live: after ESC from the ledger, the ledger and the menu were both active and both drawn. The menu opened the screen, so the menu closes it. |

## Known gaps this lane is NOT closing (they belong to other files)

- **`tools/sync-assets.mjs` mirrors `assets/final/` into `public/assets/` and nothing reads it.**
  `game/placeholder.ts` takes the real-art census with `import.meta.glob("../assets/final/**/*.png", {query:"?url"})`, which emits Vite's own (hashed, in production) URLs, and `game/mapview.ts` loads from `realAssetUrl()`. The mirror is still wired to `predev`/`prebuild` in `package.json`, so once art lands every PNG will be emitted into `dist` twice and one copy will be dead. Harmless today (`assets/final/` is empty). The fix is removing the two `package.json` script hooks and the tool — both outside this lane's scope, and `package.json` is scaffold the lanes were told not to change.
